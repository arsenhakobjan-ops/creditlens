# CreditLens
Որպես Արսեն Հակոբյանի պորտֆոլիո նախագիծ՝ այս գործիքը համադրում է վարկային վերլուծության տրամաբանությունը, Python/SQL տվյալների մշակման կառուցվածքը և QA (որակի ապահովման) սցենարները՝ պատասխանելու մեկ հիմնական հարցի. ընտանիքի եկամուտը բավարա՞ր է նոր վարկի ամսական վճարի համար։
Ստորև ներկայացված է նախագծի ֆունկցիոնալ մոդելը, հաշվարկային տրամաբանությունը (Python/SQL մակարդակով) և QA թեստային սցենարները՝ ՀՀ դրամով (AMD)։

## Գործարկել

Պահանջվում է Python 3.11 կամ ավելի նոր տարբերակ։ Լրացուցիչ փաթեթներ անհրաժեշտ չեն։

```bash
python app.py
```

Բացել http://127.0.0.1:8000 ։ Windows-ում կարելի է օգտագործել `py app.py`։ Այլ պորտի համար՝ `python app.py --port 8080`։

## Ինչպես է աշխատում

1. Մուտքագրել ընտանիքի զուտ եկամուտը, պարտադիր ծախսերն ու գործող վարկերի ամսական վճարները։
2. Նշել նոր վարկի գումարը, ժամկետը, անվանական տոկոսադրույքն ու ընթացիկ ժամկետանց օրերը։
3. Ստանալ ամսական վճարը, վարկային բեռը, մնացող գումարն ու արդյունքի բացատրությունը։

**Եկամուտ − ընտանիքի ծախսեր − գործող վարկերի վճարներ − նոր վարկի վճար = ամսվա վերջում մնացող գումար։**

Պայմանական միավոր կամ անհասկանալի «AI որոշում» չկա։

## Գնահատման տրամաբանությունը

| Արդյունք | Պայման |
| --- | --- |
| Բարձր ռիսկ | Վարկերի վճարները եկամտի 50%-ից ավելի են, մնացող գումարը բացասական է կամ ընթացիկ ուշացումը 30 օրից ավելի է |
| Լրացուցիչ ուսումնասիրություն | Բարձր ռիսկի պայման չկա, բայց բեռը 35%-ից ավելի է, պահուստը եկամտի 15%-ից պակաս է կամ կա 1–30 օրվա ուշացում |
| Նախնական անցում | Վերը նշված պայմաններից ոչ մեկը չկա |

Բարձր ռիսկի պայմանն առաջնահերթ է։ Ճիշտ 35% բեռը լրացուցիչ ուսումնասիրություն չի առաջացնում, ճիշտ 50%-ը՝ առաջացնում է։ Ճիշտ 15% պահուստը բավարար է այս ցուցադրական կանոնի համար։ Զրոյական պահուստը պահանջում է լրացուցիչ ուսումնասիրություն։

**Շեմերը նախագծի պայմանական կանոններն են, ոչ ՀՀ ԿԲ-ի, «Կամուրջ»-ի կամ որևէ բանկի պահանջները։** Դրանք սահմանված են `engine.py`-ում։ Կանոնների տարբերակը՝ `demo-am-2.0`։ Արդյունքը վարկի հաստատում կամ վերջնական մերժում չէ։

## Հայկական օգտագործման համատեքստը

- Միջերեսը և բացատրությունները հայերեն են, գումարները՝ ՀՀ դրամով։
- Ծախսերի հուշումներում ներառված են սնունդը, կոմունալը, վարձը և տրանսպորտը։
- Գործող պարտավորությունների մեջ մուտքագրվում են նաև ապառիկների վճարները։
- Եկամուտը հարկերից հետո է և վերաբերում է նույն ընտանեկան բյուջեին, որի ծախսերը մուտքագրվել են։ Չպետք է կրկնակի հաշվել սեփական հաշիվների միջև փոխանցումները։
- Անկանոն կամ սեզոնային եկամուտը մասնագետը պետք է առանձին ուսումնասիրի․ ծրագիրը դրա կայունությունը չի հաստատում։
- Պատմության ժամերը ցուցադրվում են Երևանի ժամային գոտով, իսկ տվյալների բազայում պահվում են UTC-ով։
- Տոկոսադրույքը մուտքագրում է օգտատերը․ օրինակների 18% և 24%-ը հորինված են, շուկայական առաջարկ չեն։

Հաշվարկը հավասարաչափ ամսական վճարներով դրամային սպառողական վարկի ցուցադրություն է։ Այն չի մոդելավորում արտարժութային, գյուղատնտեսական, բիզնես կամ հատուկ մարման ժամանակացույցով վարկեր։

## Անվանական և փաստացի տոկոսադրույք

Հաշվիչը օգտագործում է տարեկան **անվանական** տոկոսադրույքը։ Այն չի հաշվարկում տարեկան փաստացի տոկոսադրույքը և չի ներառում միջնորդավճարներ, ապահովագրություն կամ այլ վճարներ։ Ուստի ցույց տրված բեռը լրացուցիչ վճարների առկայության դեպքում ամբողջական չէ։

Տարբերության աղբյուր՝ [Արդշինբանկ․ տարեկան փաստացի տոկոսադրույքի հաշվարկման կարգ](https://ardshinbank.am/Information/annual-percentage-rate?lang=hy)։ Աղբյուրը օգտագործված է միայն տոկոսադրույքների տարբերությունը բացատրելու համար․ գնահատման շեմերն այդ աղբյուրից չեն։

## Ստուգումներ

```bash
python -m unittest discover -s tests -v
```

32 ավտոմատ թեստ՝ հաշվարկների, սահմանային դեպքերի, մուտքային սխալների և API-ի համար։ Ներառված են նաև Postman հավաքածու և GitHub Actions-ի թեստային workflow։

JavaScript-ի շարահյուսությունը ստուգված է։ Բրաուզերով տեսողական ստուգումը չի ավարտվել․ միջավայրում բրաուզերի ներբեռնումը ձախողվեց։ Ձեռքով ստուգման քայլերը՝ `docs/QA.md`-ում։

## Կառուցվածքը

| Ֆայլ | Դեր |
| --- | --- |
| `engine.py` | Հաշվարկներ, վավերացում և պարզ կանոններ |
| `app.py` | Տեղային HTTP API, SQLite պատմություն |
| `static/` | Հայերեն միջերես |
| `tests/` | Ֆինանսական և API թեստեր |
| `docs/` | API նկարագրություն, QA մատրից, SQL, Postman |
| `.github/workflows/tests.yml` | Ավտոմատ թեստեր GitHub-ում |

Հայտի մուտքային տվյալները, արդյունքն ու կանոնների տարբերակը պահպանվում են միասին։ Անձնական տվյալներ չեն պահանջվում։ Օգտագործել միայն հորինված թվեր։ Պատմությունը տեղային է և փոփոխությունից պաշտպանված աուդիտային գրանցամատյան չէ։ Արտաքին վարկային բյուրոյի, բանկի կամ պետական համակարգի ինտեգրում չկա։

## GitHub և տեղային գործարկում

Կոդը հնարավոր է հրապարակել GitHub-ում։ GitHub Pages-ը Python սերվեր չի գործարկում․ այս տարբերակը աշխատում է համակարգչում՝ վերևի հրամանով։ Հանրային ծառայության համար հետագայում անհրաժեշտ են առանձին տեղակայում, մուտքի կառավարում և տվյալների պաշտպանություն։

## English summary

A small Armenian-language underwriting portfolio project for fictional AMD consumer loans. It uses transparent affordability rules, local SQLite history, a JSON API, a Postman collection and 32 automated tests. No scorecard, trained model or lender policy is implied. Built with Python's standard library and plain HTML/CSS/JavaScript.
